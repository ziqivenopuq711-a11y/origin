📃 Smart Contract Overview

Origin Protocol's smart contract suite consists of upgradeable proxy contracts, strategy implementations, governance contracts, and token contracts. All contracts are written in Solidity and deployed on Ethereum mainnet.

The system uses the Transparent Proxy upgrade pattern for most contracts, with an admin multisig and timelock controlling upgrades. Critical upgrades require passing through a 48-hour timelock enforced by the governance contract.

Security researchers should pay particular attention to storage layout compatibility during upgrades, re-entrancy vectors in the Vault's multi-step operations, and any assumptions about external protocol behaviour (such as stablecoin pegs or oracle price validity).

📈 Yield Strategy Contracts

Strategies are responsible for deploying capital from the Vault into external DeFi protocols. Each strategy must implement the IStrategy interface and is governed by the Vault's allocation logic. Bugs that allow a strategy to over-report its balance or fail to return funds are considered High to Critical severity.

🔧 Key Function Signatures

These are the most security-critical functions in the OUSD Vault. Understanding the expected behaviour of each function is essential before reporting a vulnerability.

// OUSD Vault — critical entry/exit points function mint(address _asset, uint256 _amount, uint256 _minimumOusdAmount) external; function redeem(uint256 _amount, uint256 _minimumUnitAmount) external; function rebase() external; function allocate() external; function harvest(address _strategy) external; // VaultAdmin — governance-controlled function addStrategy(address _addr) external; function removeStrategy(address _addr) external; function setAssetDefaultStrategy(address _asset, address _strategy) external;

When researching the mint and redeem functions, pay particular attention to price oracle calls, slippage parameter validation, and interactions with strategy balances that may be stale or manipulated.

🔐 Upgrade Pattern & Access Controls

All core contracts use the OpenZeppelin Transparent Proxy pattern. The proxy admin is the Timelock contract, which is controlled by a 5-of-8 multi-sig operated by the Origin Protocol team.

Upgrades must be proposed via the Timelock's queueTransaction function and can only be executed after a 48-hour delay. This delay gives the community time to react to malicious or erroneous upgrade proposals.

Critical vulnerabilities include any mechanism that allows bypassing the timelock delay, upgrading a proxy without going through the multi-sig, or manipulating storage in the implementation contract to affect the proxy's state.
