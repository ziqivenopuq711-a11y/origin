Overview / Testnet Assets

Testnet Assets

Reference deployments on public testnets to support local fork testing and development validation.

⚠

No live testnet testing allowed. You must not interact with any live testnet or mainnet deployment for bug-hunting purposes. All testing must be performed on a local fork of either the mainnet or testnet state using tools such as Hardhat or Foundry.

⚠ Testnet Policy

Origin Protocol's bug bounty program explicitly prohibits any testing on live public testnets or mainnet. Testnet reference addresses are provided solely to help researchers understand the deployment architecture and set up accurate local forks for vulnerability research.

Sending transactions to testnet contracts outside of a controlled local fork environment is considered a violation of the program rules and will result in disqualification from reward eligibility. This policy protects the integrity of test environments and prevents unintentional disruption to other developers.

When preparing a Proof of Concept, use a locally forked network that mirrors the state of the target environment. Hardhat's --fork flag or Foundry's anvil --fork-url are the recommended tools for this purpose.

⚙ Setting Up a Local Fork

To reproduce a vulnerability or develop a PoC, you should create a local fork of Ethereum mainnet. Below are the recommended steps using Foundry's Anvil tool.

  1. Install Foundry by running the official installer: curl -L https://foundry.paradigm.xyz | bash
  2. Start a local fork of mainnet with: anvil --fork-url <YOUR_RPC_URL> --fork-block-number <BLOCK>
  3. Deploy or interact with the Origin contracts using the mainnet addresses listed on the Mainnet Assets page.
  4. Write your exploit script using Foundry's test framework and ensure it runs end-to-end on the local fork.
  5. Document the attack vector, root cause, and estimated impact before submitting to Immunefi.

🚫 Out-of-Scope Testnet Activities

Even on testnets, the following activities are considered out of scope and may result in permanent disqualification from the bounty program:

  • Performing denial-of-service attacks against testnet RPC endpoints
  • Spam transactions that degrade the performance of testnet infrastructure
  • Interacting with contracts owned by other projects on the same testnet
  • Attempting to manipulate shared oracle price feeds on public testnets
  • Exploiting testnet faucet contracts or bridges unrelated to Origin Protocol

All PoC submissions must clearly state the block number at which the fork was taken and include reproducible steps that allow the Origin Protocol security team to verify the findings independently.
